Conjunto de Instrucciones

El conjunto o repertorio de instrucciones es el principal atributo de la arquitectura. Define las operaciones, la codificación binaria y la estructura de direccionamiento mediante las cuales el programador gobierna al procesador.

Características del Conjunto de Instrucciones

El diseño de una instrucción se conforma de dos bloques (Identificación u Operación, y Direccionamiento) y debe cumplir 3 principios fundamentales:

Completitud

Debe permitir ejecutar todas y cada una de las operaciones que el procesador es capaz de realizar físicamente.

Ortogonalidad

Debe permitir que todas las operaciones se realicen independientemente con todos los tipos de datos aplicables.

Eficiencia

Debe evitar redundancias. Si una operación ya puede realizarse con la instrucción X, es ineficiente crear una instrucción Y paralela.

Codificación de la Operación

Código de bloque fijo Emplea una cantidad fija de bits para codificar todas las operaciones. Fácil de implementar, pero menos optimizado si hay muchas instrucciones. Se calcula con: L(co) = ⌈log2(i)⌉
Código de bloque extendido Permite mantener fijo el tamaño del formato general, extendiendo el código de operación (CO) sobre los bits de los campos de operandos que no se utilizan (p.e. en instrucciones de 1 o 0 direcciones).
Técnica de Huffman Asigna los códigos de operación más cortos a las instrucciones que estadísticamente se ejecutan con mayor frecuencia. Tiene redundancia de 0 (R = L_A - L_O), optimizando el uso de bits en arquitectura.

14 Modos de Direccionamiento

El modo de direccionamiento define la forma de determinar la Dirección Efectiva (EA) del operando y cómo obtenerlo usando Valores Numéricos (N), Índices de Registros (R) o Variables de Memoria (M).

Modos Básicos (Directos e Indirectos)

A. Inmediato

Operando definido directamente. Ej: MOV R5, 5

B. Directo o Registro

El operando está en el registro. Ej: MOV R5, R7

C. Absoluto

El operando está en una variable de Memoria. Ej: MOV R5, (1000)

D. Indirecto de Registro

Registro usado como puntero. Ej: MOV R5, (R3)

E. Indirecto de Memoria

Variable de memoria usada como puntero a otra. Ej: MOV R5, (A)

Modos Básicos (Con Auto-Actualización)

F. Autoincremento

El puntero se incrementa después del acceso. MOV R5, (R3)+

G. Autodecremento

El puntero se decrementa antes del acceso. MOV R5, -(R3)

H. Autoincremento Indir.

Puntero a arreglo de punteros que se incrementa. MOV R5, ((R3)+)

I. Autodecremento Indir.

Puntero a arreglo de punteros que se decrementa. MOV R5, (-(R3))

Modos Compuestos (Desplazamientos y Cálculo Matemático)

J. Índice o Indizado

Dirección Base + Registro Índice. MOV R5, 1000(R3)

K. Indirecto de Índice

Igual al Índice, pero referenciando a memoria. MOV R5, (1000(R3))

L. Base-Desplazamiento

Registro Base + Valor Numérico de Desplazamiento. MOV R5, R7(10)

M. Base-Desplaz. Escalado

Base + Índice multiplicado por constante de tamaño. MOV R5, 1000(R3*2)

N. Relativo (Al PC)

La base siempre es un registro (generalmente el PC) y el desplazamiento controla saltos relativos. Fundamental en instrucciones Jump/Branch.

Conjunto de Instrucciones e Instrucciones

El conjunto de instrucciones, también denominado repertorio de instrucciones y representado como I, está formado por todas las instrucciones de un procesador específico. Es el principal atributo de una arquitectura y habilita al programador para interactuar con el procesador.

Una instrucción es un tipo de dato especial que se almacena en memoria como una tira de bits y ordena al procesador realizar una de sus operaciones. Proporciona al procesador toda la información requerida para ejecutarla, principalmente la operación y los operandos.

Tipos de Instrucciones

Propósito General

  • Transferencia: mover datos entre operandos. MOVE, LOAD, STORE
  • Aritméticas: operaciones aritméticas. ADD, SUB, DIV, MUL, INC, DEC
  • Lógicas y manejo de bits: operaciones lógicas y corrimiento de bits. AND, OR, NOT, RSH, LROT
  • Comparación: compara valores de operandos y sirve de base para los saltos. CMP
  • Control de flujo: modifica la secuencia del programa para selección, ciclos y llamadas a subrutinas. JP, JR, BRN, CALL, RET
  • Entrada / Salida: acceso a direcciones del espacio de E/S. IN, OUT

Propósito Específico y Privilegiadas

  • Tratamiento de cadenas: manipulación de cadenas. COMSTR, CATSTR
  • Polinomios, funciones científicas, vectores y matrices: aceleran mediante hardware aplicaciones científicas; también contemplan datos especiales como vectores, listas y matrices. EVALUATEPOL, VADD
  • Interrupciones y excepciones: atención de dispositivos de E/S y tratamiento de condiciones anormales del procesador. INT, TRAP
  • Control del sistema: protección de memoria, detención, reinicio o detención del ordenador, entre otras funciones. HALT, NOP

Formato de Instrucción

El formato de instrucción es la estructura interna de la cadena de bits dentro de una instrucción. Se organiza en bloques, y cada bloque en campos de bits.

Bloque de identificación

Contiene un solo campo: el código de operación (CO), que indica qué operación se debe realizar.

Bloque de direccionamiento

Contiene de cero a más campos de dirección u operando. El modo de direccionamiento determina dónde está y cómo obtener el operando, es decir, la dirección efectiva (EA).

Código de operación: indica la operación.

Campo de dirección u operando: indica con qué operandos se realizará.

Valores: información necesaria para calcular la EA, como registro R, memoria M o valor numérico N.

Formato fijo: todas las instrucciones tienen el mismo tamaño, por ejemplo 32 bits.

Formato variable: las instrucciones cambian de tamaño según la operación o la cantidad y tipos de operandos.

L(F): tamaño en bits del formato de instrucción.

Codificación de la Operación

El código de operación identifica la operación a realizar. Una opción es asignar un número consecutivo a cada instrucción y expresar ese número en binario.

Ejemplo de arquitectura mínima con R2: 8 instrucciones:

MOV = 000AND = 001ADD = 010SUB = 011 DIV = 100MUL = 101JGZ = 110JEZ = 111

Al haber 8 instrucciones se requieren 3 bits para el CO.

Código de Bloque Fijo

Usa una cantidad fija de bits para codificar la operación. Es simple y fácil de implementar mediante un decodificador. Si i = n(I), entonces:

L(CO) = ⌈log2(i)⌉

Código de Bloque Extendido

Extiende el CO sobre los bits de campos de operandos que no se usan en instrucciones de varias direcciones. Permite mantener fijo el tamaño del formato y crear grupos con diferentes longitudes de CO.

Técnica de Huffman

Código variable basado en la teoría estadística de las comunicaciones. Asigna los códigos más cortos a las operaciones más frecuentes y requiere conocer su frecuencia relativa.

Ejemplos de Codificación

30 instrucciones

Si hay 10 instrucciones de 3 direcciones, 10 de 2 direcciones, 5 de 1 dirección y 5 de 0 direcciones, hay 30 instrucciones en total:

L(CO) = ⌈log2(30)⌉ = 5 bits

La potencia de 2 inmediata superior es 32, por lo que sobran dos códigos que deben tratarse como excepciones de código inválido.

15 instrucciones de 2 direcciones en 16 bits

Con dos campos de dirección de 6 bits, los operandos consumen 12 bits y quedan 4 bits para el CO. Como ⌈log2(15)⌉ = 4, el formato encaja, quedando una combinación como excepción.

Extensión del formato

Si al ejemplo anterior se agregan 30 instrucciones de 1 operando, se tienen 45 instrucciones y L(CO)=6. No caben en 16 bits y se requerirían 18 bits; al trabajar con memorias direccionables por byte, el formato podría extenderse a 24 bits, produciendo desperdicio de bits y más ciclos para traer la instrucción.

El código de bloque extendido aprovecha los bits del campo de operando que no se utilizan. Para las 15 instrucciones de 2 operandos se mantienen 4 bits de CO; las 30 instrucciones de 1 operando pueden utilizar los 6 bits libres del segundo operando, dando un CO extendido de 4 + 6 = 10 bits.

Técnica de Huffman

Huffman busca optimizar los bits empleados en el código de operación asignando códigos cortos a las instrucciones con mayor frecuencia relativa.

Instrucción Frecuencia relativa
LOAD1/4
STORE1/4
ADD1/8
AND1/8
NOT1/16
RSHIFT1/16
JUMP1/16
HALT1/16

Pasos del algoritmo

  1. Ordenar las operaciones de mayor a menor por frecuencia relativa.
  2. Crear un nodo del árbol para cada operación con su frecuencia como peso.
  3. Asociar los nodos de menor peso mediante suma y repetir hasta obtener la raíz.
  4. Etiquetar con 0 las ramas derechas y con 1 las ramas izquierdas.
  5. Recorrer el árbol desde la raíz hasta cada hoja y yuxtaponer las etiquetas para obtener el código.

Códigos del ejemplo

LOAD = 11STORE = 10 ADD = 011AND = 010 NOT = 0011RSHIFT = 0010 JUMP = 0001HALT = 0000

Longitud media del ejemplo: 2.75 bits. En bloque fijo serían 3 bits; el óptimo calculado también es 2.75 bits, por lo que la redundancia es 0.

Campos de Dirección

Los campos de dirección explicitan los operandos con los que la instrucción realizará la operación. El operando puede estar definido inmediatamente en la instrucción, directamente en un registro de propósito general o en memoria.

Número (N)

El valor es el operando o un desplazamiento para calcularlo.

Registro (R)

El valor representa el índice o número de registro.

Memoria (M)

Los valores permiten calcular la dirección efectiva.

Modos Básicos de Direccionamiento: Detalle

A. Inmediato

MOV R5, 5 → R5 ← 5.

Ventaja: obtención sencilla. Desventaja: solo permite operandos fuente y valores constantes. Uso: inicialización de variables y declaración de constantes.

B. Directo o Registro

MOV R5, R7. El operando está en un registro del CPU.

Ventajas: rapidez, operando dentro del procesador y pocos bits para codificar registros. Desventaja: intercambio continuo con memoria si hay pocos registros. Uso: datos de uso frecuente.

C. Absoluto

MOV R5, (1000) → R5 ← M(1000); también MOV R5, A.

Ventaja: acceso a cualquier dirección de memoria. Desventajas: requiere muchos bits y soporte especial para programas portables. Uso: saltos absolutos, rutinas fijas, paso de parámetros y puertos de E/S.

D. Indirecto de Registro

MOV R5, (R3) → R5 ← M(R3). El registro se usa como puntero.

Ventajas: acceso mediante registro y flexibilidad para punteros, vectores y estructuras. Desventajas: hay que cargar la dirección al registro y se limita el uso de registros. Uso: datos estructurados y paso de parámetros.

E. Indirecto de Memoria

MOV R5, (A) → R5 ← M(M(A)).

Permite implementar punteros en memoria, pero requiere múltiples accesos. Uso poco frecuente: punteros a datos estructurados y selector de variables.

F. Autoincremento

MOV R5, (R3)+ → R5 ← M(R3), R3 ← [R3]+1.

Incrementa el registro después del acceso. Es eficiente para elementos consecutivos de arreglos y permite recorrerlos de inicio a fin.

G. Autodecremento

MOV R5, -(R3) → R3 ← [R3]-1, R5 ← M(R3).

Decrementa el registro antes del acceso. Facilita recorrer arreglos desde el final hacia el inicio.

H e I. Auto-incremento y auto-decremento indirectos

MOV R5, ((R3)+) y MOV R5, (-(R3)).

Actúan como punteros a arreglos de punteros. Agilizan su recorrido, pero requieren múltiples accesos a memoria y su uso es poco frecuente.

Modos Compuestos o Desplazados

Usan más de un valor y permiten un direccionamiento dinámico y flexible. La dirección efectiva se obtiene mediante sumas entre registros y valores numéricos. Son útiles para recorrer estructuras de datos. Algunos incluyen escalación, donde un valor se multiplica por una constante que representa el tamaño del elemento.

J. Índice o Indizado

MOV R5, 1000(R3) → R5 ← M(1000 + [R3]).

Combina una dirección o registro base con un registro índice. Es versátil para acceder a arreglos y estructuras; requiere cargar y actualizar el índice.

K. Indirecto de Índice

MOV R5, (1000(R3)) → R5 ← M(M(1000 + [R3])).

Es el indirecto del modo índice. Es útil para arreglos de punteros, pero requiere múltiples accesos a memoria.

L. Base-Desplazamiento

MOV R5, R7(10) → R5 ← M([R7] + 10).

Suma una base y un valor de desplazamiento. Permite desplazarse en un área de memoria tomando la dirección base como referencia. Uso: estructuras de datos y memoria segmentada, como en arquitecturas x86 de 16 bits.

M. Base-Desplazamiento Escalado

MOV R5, 1000(R3*2) → R5 ← M(1000 + [R3]*2).

Suma la base con un índice multiplicado por una constante. Elimina la necesidad de calcular el índice por separado, aunque exige mayor control del programador. Uso: arreglos de distintos tipos de datos en memorias direccionables por byte.

N. Relativo

Es una variante del modo base-desplazamiento. La base es siempre un registro y el desplazamiento puede ser un valor o un cálculo registro-valor. El modo más utilizado es el relativo al PC, empleado en instrucciones de salto.

Codificación del Operando

La codificación del operando es similar a la del CO: se codifican el modo de direccionamiento y los valores en binario. Se prefiere la técnica de bloque fijo para los campos porque es sencilla y los modos de direccionamiento suelen ser pocos.

Bit de indirecto en PDP-11

La arquitectura PDP-11 puede estructurar internamente los bits de codificación del modo. Un ejemplo es el bit de indirecto, que diferencia el modo directo de su correspondiente indirecto usando un solo bit, el LSB del campo de MD. Si el bit es 1, el modo es indirecto. Por ejemplo, si 000 representa Directo de Registro, 001 puede representar Indirecto de Registro. Esta técnica simplifica la implementación de la Unidad de Control.

Ejemplo de Codificación de Instrucción: Formato R de PDP-11

El formato R se emplea para modos basados en registro. La sintaxis indicada es OP F, D. Para el ejemplo ADD (R5), R3, se supone CO(ADD) = 0010.

CO00104 bits
RfR5 = 1016 bits de operando fuente con MD

En el ejemplo, el operando fuente (R5) utiliza MD indirecto de registro (001) y el operando destino R3 utiliza MD directo de registro (000).
